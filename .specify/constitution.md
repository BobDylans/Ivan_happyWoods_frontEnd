# 🌿 Ivan_HappyWoods 项目宪法

**生效日期**: 2025-10-21

---

## 📜 项目使命

Ivan_HappyWoods 致力于创建一个**温暖、自然、智能**的 AI 对话系统，通过优雅的设计语言和流畅的交互体验，让人机对话变得更加愉悦和高效。

---

## 🎯 核心价值观

### 1. 用户至上 (User-Centric)
- **MUST**: 所有功能设计必须从用户需求出发
- **MUST**: 保持界面简洁直观，降低学习成本
- **SHOULD**: 提供多种交互方式（文本、语音、快捷键）
- **SHOULD**: 优化移动端体验，确保跨设备一致性

### 2. 设计一致性 (Design Consistency)
- **MUST**: 严格遵循 HappyWoods 设计系统规范
- **MUST**: 所有间距必须是 4px 的倍数（4px 基线网格）
- **MUST**: 保持温暖琥珀色主题的视觉统一
- **MUST**: 动画时长遵循设计系统预设（150ms-500ms）
- **SHOULD**: 复用现有组件，避免重复造轮子

### 3. 无障碍优先 (Accessibility First)
- **MUST**: 所有文本对比度达到 WCAG AAA 标准（≥7:1）
- **MUST**: 所有交互元素支持键盘导航
- **MUST**: 提供完整的 ARIA 标签
- **MUST**: 支持 prefers-reduced-motion 媒体查询
- **SHOULD**: 支持屏幕阅读器

### 4. 性能至上 (Performance First)
- **MUST**: 首屏加载时间 < 2 秒（3G 网络）
- **MUST**: 动画保持 60fps（桌面端）
- **MUST**: 使用代码分割和懒加载优化包体积
- **SHOULD**: 实现虚拟滚动优化长列表
- **SHOULD**: 使用 Service Worker 实现离线支持

### 5. 类型安全 (Type Safety)
- **MUST**: 所有代码使用 TypeScript strict 模式
- **MUST**: 禁止使用 `any` 类型（除非明确必要）
- **MUST**: 组件 Props 必须有完整类型定义
- **SHOULD**: 使用 Zod 或类似工具验证 API 响应

### 6. 代码质量 (Code Quality)
- **MUST**: 所有代码必须通过 ESLint 检查
- **MUST**: 遵循 React 最佳实践（Hooks 使用规则）
- **MUST**: 函数保持单一职责，避免过长函数（< 50 行）
- **SHOULD**: 核心功能覆盖单元测试（目标 > 80%）
- **SHOULD**: 使用有意义的变量和函数命名

### 7. 安全性 (Security)
- **MUST**: 所有用户输入必须验证和清理
- **MUST**: API 密钥不得硬编码在前端代码中
- **MUST**: 使用 HTTPS 进行所有网络通信
- **SHOULD**: 实现 CSP（Content Security Policy）
- **SHOULD**: 定期更新依赖包，修复安全漏洞

---

## 🏗️ 技术架构原则

### 前端架构
- **MUST**: 使用 Next.js 15+ 的 App Router
- **MUST**: 使用 React 19+ 的最新特性
- **MUST**: 使用 TypeScript 5.3+ strict 模式
- **MUST**: 使用 TailwindCSS 4+ 进行样式管理
- **SHOULD**: 使用 Zustand 进行轻量级状态管理
- **SHOULD**: 使用 Framer Motion 实现动画效果

### 组件设计
- **MUST**: 所有组件必须是纯函数或 React 函数组件
- **MUST**: 使用 CVA (class-variance-authority) 管理变体
- **MUST**: 组件必须支持 `className` 属性覆盖
- **SHOULD**: 优先使用受控组件
- **SHOULD**: 提供完整的 JSDoc 注释

### 目录结构
- **MUST**: 遵循 Next.js 约定的目录结构
- **MUST**: UI 组件放在 `src/components/ui/` 下
- **MUST**: 业务组件按功能模块分组
- **SHOULD**: 保持文件路径简短清晰

### API 集成
- **MUST**: 所有 API 调用封装在 `lib/api-service.ts` 中
- **MUST**: 使用环境变量管理 API 端点
- **MUST**: 实现统一的错误处理机制
- **SHOULD**: 支持请求取消和重试

### Git 工作流
- **MUST**: 使用 feature 分支开发新功能
- **MUST**: Commit 信息遵循约定式提交规范
- **MUST**: 合并前必须通过 lint 和 type check
- **SHOULD**: PR 需要代码审查
- **SHOULD**: 保持 commit 历史清晰

### 发布流程
- **MUST**: 使用语义化版本号（Semantic Versioning）
- **MUST**: 更新 CHANGELOG.md 记录变更
- **MUST**: 生产构建前运行完整测试
- **SHOULD**: 使用 CI/CD 自动化部署

## 🚫 禁止事项

### 代码层面
- ❌ **禁止**使用内联样式（除非动态计算）
- ❌ **禁止**直接修改 DOM（使用 React 状态）
- ❌ **禁止**使用 `var` 声明变量
- ❌ **禁止**使用 `console.log` 提交到生产代码
- ❌ **禁止**绕过 TypeScript 类型检查

### 设计层面
- ❌ **禁止**偏离设计系统规范的自定义样式
- ❌ **禁止**使用非 4px 倍数的间距值
- ❌ **禁止**使用未定义的颜色值
- ❌ **禁止**添加无意义的动画效果

### 依赖管理
- ❌ **禁止**添加未经评估的大型依赖库
- ❌ **禁止**直接修改 node_modules 文件
- ❌ **禁止**使用已废弃的依赖包
